# Architecture

The main local WebView owns React routing/filter state, library cards, series grouping, notes, and a fixed player strip. Filtering and series navigation never call `open_player`. Selecting a title opens the official library and requests a click of its real Listen now control. launch.js requires an exact ASIN association, rejects containers identifying other books, clicks only one unique visible enabled control and falls back to manual selection after bounded lookup/click deadlines. Pending requests survive sign-in navigation but are cleared by manual sign-in/library navigation or ending the session. Successful full-player telemetry records a sanitized launch address in official_launches, containing only the exact ASIN and allowlisted delivery/launch flags. Later openings replay that observed address with cloud resume enabled; sample detection invalidates it and retries through the library. Library matching also recognizes player links and row identifiers, and can submit the actual library search form once per launch. DOM-ready signaling starts it before full page load, repeated injection preserves active work, and a filtered MutationObserver resumes scans for in-place search results. Click retries use backoff, reset on a replacement DOM control, and stop at a bounded deadline. The fast path checks known Audible controls before generic matching; scroll is immediate. An already loaded title is reused without navigating.

`PlaybackAdapter` is the only frontend playback dependency. `DemoAdapter` produces deterministic simulated state; `OfficialAdapter` invokes narrowly scoped Rust commands. Rust validates the caller window, action, numeric input, and ASIN before evaluating a serialized command in the official page. No user content becomes executable JavaScript.

The official WebView permits HTTPS navigation only to the exact audible.com, www.audible.com, amazon.com and www.amazon.com hosts for the US sign-in flow. Remote pages have no Tauri capabilities and cannot query SQLite or invoke local commands. A JavaScript bridge finds an HTML audio/video element and reports state through an intercepted `audible-state:` navigation. Rust cancels that navigation and sends telemetry only to the main window. Telemetry is untrusted and must never authorize filesystem, authentication or network actions. This proof-of-concept transport and selector strategy needs a real WebView2 test, including CSP and navigation behavior.

SQLCipher stores metadata and notes with parameterized statements. A random database key and API credentials are protected with Windows user-bound DPAPI in separate development/release directories. Account OAuth and official playback use the same persistent account-web-session WebView2 data directory with persistent browsing by default and optional private website sessions; cookies remain browser-managed locally, never exported to the frontend. The refresh-token website-cookie bootstrap was removed from playback after live tests still required sign-in. Forget website sign-in deletes shared-profile cookies and closes playback; Sign out also deletes the API credentials. Sign-out checks cookie removal even with no playback window by opening a hidden local cleanup view. Non-cookie site data and cached books/notes remain. See PRIVACY.md.

Frontend telemetry validates finite numeric ranges and boolean flags and disables controls when reports stop. Next implementation steps: Rust-side typed telemetry validation; explicit capability acknowledgements per feature; nonblocking database worker and migrations; library export schema fixtures; marketplace allowlist; secure unofficial metadata login using Windows Credential Manager or DPAPI for secret material; token refresh and revocation; catalog series provider; account-specific caches; user-initiated logout that clears the official profile and cached personal data. Native sign-in and logout lifecycle is not complete yet.

## Native API provider and mini-player

The metadata.rs provider authenticates through an Amazon WebView using the shared local account profile and PKCE callback. It exchanges codes and refreshes tokens in Rust, stores credentials through the separate Windows-protected account store and allows only fixed HTTPS metadata endpoints with redirects disabled. Library responses are normalized before caching. The API provider is separate from OfficialAdapter and does not handle audio.

The mini-player is a local always-on-top WebView using index.html?mini=1. Its capability grants only event subscription; Rust explicitly permits this label for playback/current-state/show-window commands and rejects it for database, auth and library mutation commands. The PlayerHub shares typed state with both local windows and associates checkpoints with the selected ASIN. Closing the mini-player leaves the official audio WebView alone. Hiding the official WebView preserves it; hidden audio/timer behavior needs runtime testing.


## Fresh-account registration boundary

New account connections default to the original iOS metadata profile. Previously registered Android accounts keep their serialized profile for refresh. The frontend does not select the retired streaming-test profile. `exchange_registration` accepts only the fixed Amazon HTTPS registration endpoint outside unit tests and parses the response independently from storage. `finish_registration` checks the active attempt, requires protected persistence to succeed, and only then exposes a connected state. `connection` returns only readiness, profile and sanitized status; never credentials. Token lifetimes accept finite decimal/integer JSON values or strings, round down, and reject invalid/out-of-range lifetimes. The same parser is used on refresh.

The account UI subscribes before reading state, checks again on focus, and polls locally while authorization is finishing. A browser close after an accepted callback does not cancel the approved exchange; closing before callback cancels it. PKCE and exact trusted callback origins remain enforced. Fresh-account regression tests run a loopback HTTP provider with synthetic responses, then exercise the real DPAPI account store and reloaded connection state. No real credentials or Amazon requests are used by those tests.
