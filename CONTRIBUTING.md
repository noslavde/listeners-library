# Working on Listener’s Library

Write source for the next person who needs to understand it. Compact production
bundles are generated by the build tools; the source should remain expanded,
indented and easy to navigate.

New to the project? Read the [developer walkthrough](docs/DEVELOPER_GUIDE.md), then
use the [complete source index](docs/SOURCE_INDEX.md) to find each module's purpose.
Keep module/function comments accurate when changing behavior; document units,
account lifetimes, side effects and failure assumptions rather than every statement.

## Source map

| Location                                       | Responsibility                                                                     |
| ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| `src/main.tsx`                                 | React startup, error boundary and main/mini/cover window selection                 |
| `src/App.tsx`                                  | Main screen, sections, library state and playback orchestration                    |
| `src/components/`                              | Shared screen components extracted from orchestration                              |
| `src/features/reviews/`                        | Local reviews UI, rating display, account-scoped hook, model and tests             |
| `src/MiniPlayer.tsx`                           | Shared main/mini player controls; embedded mode uses the main window               |
| `src/HighlightsPanel.tsx`                      | Saved moments UI and explicit annotation-sync actions                              |
| `src/style.css`                                | Shared styles, grouped by labeled sections; later rules can override earlier rules |
| `src/highlights.css`, `src/annotationSync.css` | Saved-moments and annotation-sync styles                                           |
| `src-tauri/src/`                               | Native window, account, encrypted storage and playback modules                     |
| `src-tauri/src/metadata/`                      | Account/service protocol adapters and their tests                                  |
| `src-tauri/src/*.js`                           | Readable scripts injected into the official website; keep these as source          |
| `scripts/`                                     | Build, release and notice-generation tooling                                       |
| `docs/`                                        | User guides, testing checklists, design and security notes                         |

Older shared frontend modules remain at the `src/` root. Group new substantial
features into `src/features/`; move older modules when a focused refactor makes
their relationships clearer. Avoid reorganizing working account or playback code
just to make the directory tree symmetrical.

## Formatting

Use an editor that honors `.editorconfig`. Prettier uses two spaces for supported
frontend, script and documentation formats; rustfmt uses Rust's standard layout.
Keep complete function bodies and JSX expanded. Use meaningful parameter and
function names, keep related logic together, and explain constraints or surprising
decisions in comments. Prefer named declarations for components and larger helpers.

```powershell
npm run format
npm run format:check
```

These commands cover all supported authored files, including new files. Generated
output, dependency directories, local experiments and installers are excluded.
Do not hand-format generated lockfiles, dependency notices or build output.

## Verify changes

```powershell
npm test
npm run build
npm run check:release
npm run test:native -- --release --locked
```

Native builds need the Windows Rust/MSVC toolchain and Perl for SQLCipher/OpenSSL.
The npm native-build wrapper configures the project's available Perl environment.
The existing Windows workflow runs the format check as well as build/test checks.

Formatting and source moves should preserve behavior. After UI moves, also check
the changed screen and that switching sections does not restart playback. A browser
demo cannot prove real Audible playback or durable Windows account storage.
